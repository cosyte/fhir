Validating a resource against a profile no longer passes a constraint it did not check. A profile that narrowed `value[x]` to `Quantity`, set a `maxLength`, or limited a reference with `targetProfile` used to report a resource that broke it as valid, with nothing said. Now each such constraint is checked, or reported as not checked:

- A `choice[x]` occurrence of a type the profile does not list is `PROFILE_TYPE_MISMATCH` (error).
- A `Reference` whose target is of a type no `targetProfile` allows is `PROFILE_REFERENCE_TARGET_MISMATCH` (error). The type is read from the target when it is in the resource's `contained` set or, for a Bundle, its entries, else from the reference's own `Type/id`. `Resource` allows any target, `DomainResource` any but a `Binary`, `Bundle` or `Parameters`, and `MetadataResource`, `CanonicalResource` or an element type decides nothing and is reported not checked. A slicing `type` discriminator that names `MetadataResource` or `CanonicalResource` is reported `PROFILE_SLICE_UNCHECKED`, as `Resource` already was.
- A string longer than the element's `maxLength` is `PROFILE_MAX_LENGTH` (error), counted in UTF-16 code units as the reference validator counts it.
- A number outside an integer or decimal `minValue[x]` or `maxValue[x]` is `PROFILE_MIN_VALUE` or `PROFILE_MAX_VALUE` (error), compared exactly.
- A list of type profiles or target profiles is met by meeting any one of them. A quantity with a `comparator` where the profile names R4's `SimpleQuantity` and no other profile is `INVARIANT_VIOLATED` with the key `sqty-1` (error); beside another profile it is reported not checked.
- Every other constraint on a present element that no layer checks is `PROFILE_CONSTRAINT_UNCHECKED` (information), and the new `uncheckedConstraint` field names its kind, one of `PROFILE_UNCHECKED_CONSTRAINTS`: a type profile, a target profile that is a constraining profile or whose target's type cannot be read, a `maxLength` on a non-string, a non-numeric value range, a `required` or `extensible` binding other than the R4 value set the structural schema enumerates for that element, slice order, a slice's own invariant, an invariant on a primitive, and anything in the element definition the profile model does not read. It reaches an `OperationOutcome` as `issue.details.text`.

What a caller sees change: a resource that broke one of these constraints was `valid: true` and is now `valid: false`; a resource validated against a real profile (a US Core one, the veterinary starter) now carries informational `PROFILE_CONSTRAINT_UNCHECKED` findings where it carried none, which do not change `valid`. A caller that treats every finding as a failure should filter on `severity`. `ElementDefinition` gains `maxLength`, `minValue`, `maxValue` and `unmodeled`; `RequiredBinding` gains `valueSet`; `ProfileOptions` gains `schema`, which `validateResource` fills; `validationIssue` takes an optional seventh argument, the unchecked kind. Nothing a caller passes today has to change.
