An array that holds an object is now read as a list of elements whichever member comes first, so an object written after a string, number, boolean or `null` keeps its content. `parseResource('{"resourceType":"Patient","extension":["x",{"url":"http://example.com/syn-ext","valueString":"syn"}]}')` used to read the object as an empty value, and `serializeResource` then wrote `["x",null]`; the object is now an element with its `url` and `valueString`, and the write gives back the document as it was read.

What a caller sees change: in such an array every item is a complex node. An object keeps its members, and a string, number, boolean or `null` beside it is an empty complex node that keeps its text and draws `UNKNOWN_PROPERTY` at its own position (before, the object's position drew it). `readSafety` lists that position on `notAssessed`, so the resource is not safe to summarize, in either order: an array whose object came first used to read safe with a string beside it. One field of the readout moves with this: `Observation.status` written as `["entered-in-error",{}]` used to read `retracted: true`; it now reads `retracted: false`, with `Observation.status` on `unreadableNegationCodes` and `Observation.status[0]` on `notAssessed`, and stays not safe to summarize. A caller that reads `retracted` alone sees it flip, so read `safeToSummarize` first. A `_`-sibling written beside such an array is not read, and draws `MISPLACED_PRIMITIVE_EXTENSION`, as it already did when the object came first. An array of strings, numbers, booleans, `null`s and inner arrays with no object reads as before.
