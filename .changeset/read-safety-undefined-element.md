An element the FHIR definitions do not define is never read as safe. `readSafety` now checks every element of a resource of a type it assesses, at every depth (backbone elements, datatypes, extensions, a primitive's extensions, contained resources and Bundle entries), against the union of what R4 and R4B define there. An element neither release defines, such as `entry` on a Patient, `Entry` or `Contained` in the wrong case, an extra key on a Bundle entry or a Coding, a member of an object where a primitive belongs, or a `resourceType` on a Bundle entry, is listed on `notAssessed` by its own location, `safeToSummarize` is `false`, and `assertSafeToSummarize` throws. So is an XML element in a namespace other than its parent's, however the namespace is declared (a prefix, a default `xmlns`, or `xmlns=""`), which the reader now marks as `foreignNamespace` on the node; only the narrative `div` in XHTML is exempt. An XML root in a namespace other than FHIR's is listed by its root's location. A value written where the definitions put only a complex type, such as `"code": "x"` on an Observation, is listed too, though `validateResource` does not report it as an unknown element. Before, such a document read `safeToSummarize: true`. `validateResource` reports the same elements as `UNKNOWN_ELEMENT` at every depth, where before it checked only the resource's own members and none at all on a Bundle or a Practitioner. A document that writes only defined elements reads as before. What a caller must change: a document with an element the definitions do not define is now declined, so read `notAssessed` to see where, and expect more `UNKNOWN_ELEMENT` warnings (errors in strict mode) on such documents.
