# scripts/phi-allow-list.txt
#
# PHI-scan allow-list, the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. A FHIR resource *could* carry an inline
# `"_synthetic": true` marker, but that would corrupt the very round-trip the
# fixtures prove, so this allow-list is the synthetic-fixture declaration
# mechanism instead, the same approach `@cosyte/dicom` uses for binary `.dcm`
# files and `@cosyte/x12` for byte-strict `.edi`.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word (HumanName family / given /
#                         text), matched case-insensitively
#   DOB <YYYY-MM-DD|YYYY> synthetic date of birth (birthDate / deceasedDateTime),
#                         normalized to digits before comparison
#   ADDR <street line>    synthetic street address (Address.line / .text),
#                         matched case-insensitively
#   ID <value>            synthetic id that legitimately matches an SSN- /
#                         9-digit- / phone-shaped value (identifier / telecom)
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.

# --- Synthetic patient / person names ---
# The canonical FHIR R4 patient-example person (Peter James Chalmers) plus the
# spec's "Jane Q Public" alias, both published synthetic examples.
NAME CHALMERS
NAME PETER
NAME JAMES
NAME JANE
NAME PUBLIC
# The repo's own coined synthetic tokens (self-evidently fake).
NAME SYNTHFAMILY
NAME SYNTHGIVEN
NAME SYNTHMIDDLE
# The two canonical anonymous-party placeholder surnames. Neither identifies
# anyone: "Roe" and "Doe" are what a legal filing uses for a party whose name is
# withheld, and this suite uses them for the same reason.
NAME ROE
NAME DOE

# --- HL7's published R4 example documents, vendored under
# --- test/__fixtures__/fhirpath-suite/ from FHIR/fhir-test-cases at tag 1.7.67
# The vendored corpus is HL7's own published example data, redistributed under
# Apache-2.0 beside its LICENSE.txt. Nothing below is a real person: every token
# is one HL7 itself prints in the R4 specification's example documents. FOUR of
# the eleven vendored inputs (patient-example.xml, patient-example-period.xml,
# patient-name-extensions.json, patient-container-example.json) carry the tokens
# the scanner names; the remaining seven carry none.
#
# The canonical patient-example person is Peter James Chalmers, already declared
# above. These are the tokens that person's OTHER names add: the "maiden" name
# Windsor, the "usual" given name Jim, and the "old" French spelling
# "Bénédicte du Marché".
NAME WINDSOR
NAME JIM
NAME DU
# SCANNER-VISIBLE FRAGMENTS, NOT WORDS. The two accented tokens are written in
# the vendored XML with numeric character references (`du March&#xE9;`,
# `B&#xE9;n&#xE9;dicte`), and the XML scanner reads the `value="…"` attribute as
# raw bytes, so it tokenizes on non-letters and sees `March` + `xE`, and `xE` +
# `dicte`. Declaring the fragments is the token-level remedy the overrides file
# asks for; declaring the whole file would not be. Do not "tidy" these into
# `MARCHÉ` / `BÉNÉDICTE`: those forms never reach the comparison.
NAME MARCH
NAME XE
NAME DICTE
# patient-container-example.json writes `name.text` as the literal placeholder
# "some-name", which tokenizes to two ordinary English words. Neither is a
# surname anyone here carries; both are declared because the scanner cannot tell
# a placeholder from a name and must not be taught to guess.
# THESE TWO ARE THE BROADEST ENTRIES IN THIS FILE AND THE COST IS PERMANENT.
# `SOME` and `NAME` are ordinary words, so a FUTURE fixture carrying either as a
# real surname would clear the gate on these lines rather than on its own merit.
# That is the price of a token-level declaration over a whole-file bypass and it
# is the cheaper of the two, but it is a price: if a later change can retire the
# `some-name` placeholder from the vendored bytes, delete both lines with it.
NAME SOME
NAME NAME

# --- Synthetic dates of birth (birthDate) ---
DOB 1974-12-25
DOB 1970-01-01
DOB 1980-01-01
# Year-only precision, the deceased[x] choice-type case. `deceasedDateTime` is
# gated by the same rule as `birthDate` (both are dates that identify), and FHIR
# `dateTime` permits a bare year, so this is the shape a year-precision death
# date arrives as.
DOB 2020

# --- Synthetic street addresses (Address.line / Address.text) ---
# The one street line the canonical R4 patient-example prints, in both
# patient-example.xml and patient-example-period.xml. "Erewhon" is Samuel
# Butler's anagram of "nowhere", which is the point: HL7 chose a street in a
# place that does not exist.
ADDR 534 Erewhon St

# --- Synthetic identifiers (identifier.value / telecom.value) ---
ID SYN-0001
# The two ContactPoint.value numbers the canonical R4 patient-example prints,
# spelled here as the scanner compares them: digits only, punctuation stripped.
# `(03) 3410 5613` is an Australian number whose 03 area code plus 3410 exchange
# HL7 uses across the R4 examples, and `+33 (237) 998327` is its French
# counterpart. Neither uses the 555 fake-exchange convention the scanner keys
# on, which is why each needs a line of its own rather than a shape rule.
ID 0334105613
ID 33237998327

# --- Reserved / test email domains (RFC 2606 + FHIR example host) ---
EMAILDOMAIN example.com
EMAILDOMAIN example.org
EMAILDOMAIN example.net
EMAILDOMAIN hospital.example.org
# NOT a mail domain. This package spells a diagnostic `IssueCode@FHIRPath`, and
# `UNKNOWN_PROPERTY@Patient.name` is one `@` between two dotted tokens, which no
# email recogniser can tell from an address by shape (`.name` is a real TLD). The
# tests assert on those strings. Declared here, one domain at a time, rather than
# by a shape rule in the scanner: a rule keyed on the shape covered every
# capitalised domain in every source file and lost a hit the scanner already had.
EMAILDOMAIN patient.name
# This package's own contact address, `hello@cosyte.com` in `package.json`. Not a
# reserved domain: it is OURS, which is the reason it is declarable. It is the
# maintainer's mailbox, so it is not an address a patient is ever recorded at,
# and the blast radius is the one domain. It became reachable when the sweep
# started reading the bytes git carries repo-wide; before that no route opened
# `package.json` at all.
EMAILDOMAIN cosyte.com
